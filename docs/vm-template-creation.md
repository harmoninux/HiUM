# 模板创建（Alpine 一键开箱）—— 功能设计

> 状态：已实施（2026-09-12，真机验证通过）。
> v2 变更：入口从「向导内分段」改为「新建按钮弹菜单分流」，模板/自定义
> 是**两套互相独立的创建流程**（独立组件、独立模态），互不知道对方存在。
> 关联：`machine-workshop-interaction.md`（自定义向导交互稿）；
> 实现入口 `entry/src/main/ets/pages/VmList.ets`（新建按钮）+
> `VmWizard.ets`（自定义流程）+ 新增 `VmTemplate.ets`（模板流程）。

## 0. 目标

把「创建虚拟机」拆成两条**独立**路径：

- **模板**：面向普通用户。当前只提供 **Alpine Linux** 一个模板，只暴露
  **CPU 架构 / CPU 核数 / 内存 / 系统盘大小** 4 个自由度，其余全部默认
  （网络开启）。点「创建」后自动下载 Alpine ISO、建盘、落档，得到一台
  可直接启动的虚拟机。
- **自定义**：即现有的 6 步机器工坊向导（`VmWizard`），面向进阶用户，
  自由度与交互完全不变。

### 非目标

- 不做模板市场/多模板（Android-x86、DOS 等留扩展位，见 §6）。
- 模板不是锁定配置：创建产物是与手工创建**完全同构的 `VmProfile`**
  （schema 不变、无模板标记），创建后在编辑页/存储管理里仍可改任何参数。
- 不自动启动虚拟机：创建完成即回列表，启动由用户触发
  （首启路径已有内置 ISO 缺失重试兜底，见 §4）。

## 1. 入口：「+ 新建」弹出菜单分流

首页「+ 新建」按钮不再直接开向导，改为 `.bindMenu` 弹**原生菜单**
（`Menu/MenuItem`——必须用原生组件，自定义拼装的菜单 Button 样式嘈杂，
见 `VmManage.vmOpsMenu` 的既有结论）：

```
        ┌─ + 新建 ─┐
        └────┬─────┘
             ▼
      ┌──────────────┐
      │  模板创建     │  → 打开模板流程（VmTemplate 模态）
      │  自定义创建   │  → 打开手工向导（VmWizard 模态，现状不变）
      └──────────────┘
```

**分流规则**

- **菜单顺序：模板创建在前、自定义创建在后**——模板是普通用户主路径，
  第一眼看到；自定义是进阶入口，沉底。
- 两个流程是**两个独立组件、两个独立模态开关**（`showWizard` /
  新增 `showTemplate`，同在 `Index` `@Provide`），各自挂载、各自关闭，
  不共享状态、无切换关系——用户在菜单里一次选定一条路。
- 「自定义创建」= 今天的 `openWizardNew()`，行为一字不动。

## 2. 模板流程（VmTemplate，单页模态）

复用向导的模态壳（内嵌居中浮层 + 遮罩，样式对齐 `VmWizard`），
内容为**单页表单**，无步骤条：

```
┌─ 模板创建 ────────────────────────────────────────────┐
│  ┌────────────────────────────────────────────────┐   │
│  │ Alpine Linux 3.21                        内置ISO│   │
│  │ 迷你安全发行版 · 文本模式 · ~60MB 镜像          │   │
│  └────────────────────────────────────────────────┘   │
│                                                       │
│  CPU 架构   [x86_64] [aarch64] [i386] [arm] …(6 项)   │
│  CPU 核数   ◄───●────────►  2 核                      │
│  内存       ◄─────●──────►  1024 MB                   │
│  系统盘     [4G] [8G] [16G] [32G] [64G] …             │
│                                                       │
│  其余按推荐默认：网络开启 · 动态qcow2 · 声卡开          │
│                                                       │
│  ── 创建后自动下载 Alpine 镜像（约 63MB，国内镜像）──   │
│                                                       │
│                   [ 取消 ]      [ 创建虚拟机 ]         │
└───────────────────────────────────────────────────────┘
```

**交互规则**

- 模板卡片当前只有 Alpine 一张，恒选中（仅信息展示：版本、特点、镜像体积）。
- **CPU 架构**：6 个内置 ISO 已全覆盖的架构
  （x86_64 / i386 / aarch64 / arm / loongarch64 / riscv64，
  见 `isoDl.specFor`）；切换架构只影响默认值映射与待下载的 ISO，不联动其他可见项。
- **核数 / 内存**：Slider（控件与档位对齐向导步骤③；默认 2 核 / 1024MB）。
- **系统盘大小**：档位列（4/8/16/32/64GB，默认 8GB，动态分配 qcow2）。
- **名称不询问**：自动命名 `Alpine <版本> <架构>`（如 `Alpine 3.21 x86_64`），
  与现有 VM 重名时追加 ` 2`、` 3`… 后缀去重（查 `VmStore.list()` 现有名）。
- 「创建虚拟机」按钮在下载/建盘中禁用并显示进度（见 §4）；「取消」随时可点，
  未落盘前直接关模态不留痕迹。

## 3. 模板固定默认值

模板产物 = 手工向导全默认 + 下列覆盖。固定项取值及出处：

| 项 | 值 | 出处/说明 |
|---|---|---|
| 板卡/固件/显卡 | 按架构走 `fitBoard`/`fitVga` + 向导默认（pc/SeaBIOS/std 等） | 与手工向导全默认完全一致 |
| CPU 机型 | 空（qemu 默认） | 同向导 `cpuModel=''` |
| TCG | mttcg 开、tb-size 1024 | 向导默认 |
| 系统盘 | 动态分配 qcow2，`vms/<id>.qcow2` | 大小见表单；新建空白盘 |
| 光盘 | `vmDataDir/builtinIsoFor(arch)`，`bootFromCdrom=true` | 首次启动从 ISO 引导进 Alpine live |
| 内核引导 | 无 | — |
| 网络 | **开启**，无端口转发，无共享文件夹 | 模板语义「网络开启」 |
| 串口 | 交互模式 | 向导默认 `serialInteractive=true` |
| 增强 | rng/balloon 关、audio 开 | 向导默认 |
| 临时会话 | 关 | — |

## 4. 创建流水线

点「创建」后顺序执行（任一失败即停并 toast 具体原因，按钮恢复）：

1. **落档建盘**：`newProfileId()` → 按 §3 装配 `VmProfile` →
   `createDisk` 建空白 qcow2 → `VmStore.save`。
   （与手工向导 `finish()` 同序：先建盘后落档，取消/失败不留孤儿档。）
2. **下载 ISO**：`ensureBuiltinIso(ctx, vmDataDir, arch, onPct)`，
   按钮区显示 `下载中 N%`（已有机制：tuna → ustc 镜像顺序回退）；
   **ISO 已存在则秒过**（多 VM 同架构共享一份，见 `isoDl`）。
3. **完成**：toast `已创建「<名称>」`，关闭模态，列表刷新（`vmListVersion`）。

**下载失败不毁单**：VM 已落档则保留——`VmConsole.startVm` 本就有
「引导光盘是内置 ISO 且未下载 → 先下载再启动」的首启重试
（`VmConsole.ets startVm`），用户后续启动时自动补下，toast 说明即可。

## 5. 与现有机制的衔接点

| 机制 | 复用方式 |
|---|---|
| 原生菜单 | 「+ 新建」`.bindMenu(Menu{ MenuItem×2 })`，样式对齐 `VmManage.vmOpsMenu` |
| 模态壳 | `VmTemplate` 复用 `VmWizard` 的浮层结构/遮罩/token（独立组件，只借样式不嵌向导） |
| `assemble()` 装配 | 模板流程自己的精简装配函数（默认值常量 + 4 个表单项），产物 schema 相同 |
| `isoDl.ensureBuiltinIso` | 创建时主动调；首启重试兜底已在 `VmConsole` |
| `builtinIsoFor(arch)` | 光盘路径与下载目标的一致性保证 |
| 自动命名去重 | `VmStore(filesDir).list()` 取现有名集合 |
| 校验 | 模板仅 4 项且全是档位/滑块，无非法输入面，无需红字校验链 |

## 6. 扩展位（本次不实施）

- **模板注册表**：模板抽成数据驱动条目
  `{ id, name, desc, archs, defaults, iso: 'builtin' | '自备' }`，
  Alpine 为首条；后续 Android-x86（需自备镜像，标注灰字）等按
  `machine-workshop-interaction.md` §1 的卡片样式扩充；多模板时
  模板页卡片变列表单选，表单区不变。
- 模板创建后可选「创建并启动」复选（默认关）。

## 7. 边界与决策记录

- **无网/下载失败**：见 §4——保档 + 首启重试，不阻塞创建。
- **重复快速点创建**：建盘/下载期间按钮禁用。
- **同架构多台模板机**：ISO 共享不重复下载；系统盘各自独立。
- **为什么不做名称字段**：模板语义是「零决策开箱」，名称自动可后改
  （编辑页已有改名入口）；若评审认为需要，加一行可空文本框（空=自动命名）。
- **为什么是两个独立组件而非向导内分段**（v2 决策）：模板/自定义面向两类
  用户、无中途互换诉求；独立组件让模板流程保持极简单页，也给向导留「我永远
  是 6 步」的干净边界，后续各自演进互不牵扯。
