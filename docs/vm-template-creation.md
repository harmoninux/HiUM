# 模板创建（多模板：Alpine 一键开箱 / Windows 安装）—— 功能设计

> 状态：已实施（2026-09-12 Alpine 单模板真机验证通过；2026-09-19 扩展为多模板，
> 新增 Windows XP / Windows 7）。
> v2 变更：入口从「向导内分段」改为「新建按钮弹菜单分流」，模板/自定义
> 是**两套互相独立的创建流程**（独立组件、独立模态），互不知道对方存在。
> v3 变更：模板卡片变列表单选（§6 预留形态落地），新增 Windows XP/7（x86_64
> 与 i386 双版本），schema v7 增加磁盘接口（iface）与网卡型号（net.model）。
> 关联：`machine-workshop-interaction.md`（自定义向导交互稿）；
> 实现入口 `entry/src/main/ets/pages/VmList.ets`（新建按钮）+
> `VmWizard.ets`（自定义流程）+ `VmTemplate.ets`（模板流程，注册表内联）。

## 0. 目标

把「创建虚拟机」拆成两条**独立**路径：

- **模板**：面向普通用户。模板注册表当前 3 条（Alpine / Windows XP /
  Windows 7），表单只暴露 **CPU 架构 / CPU 核数 / 内存 / 系统盘大小** 4 个
  自由度（切模板时重置为该模板默认）。Alpine 点「创建」后自动下载内置 ISO，
  得到一台可直接启动的虚拟机；Windows 需自备安装镜像（可跳过，创建后补挂）。
- **自定义**：即现有的 6 步机器工坊向导（`VmWizard`），面向进阶用户，
  自由度与交互完全不变。

### 非目标

- 不做模板市场/多模板（Android-x86、DOS 等留扩展位，见 §6）。
- 模板不是锁定配置：创建产物是与手工创建**完全同构的 `VmProfile`**
  （schema 不变、无模板标记），创建后在编辑页/存储管理里仍可改任何参数。
- 不自动启动虚拟机：创建完成即回列表，启动由用户触发
  （首启路径已有内置 ISO 缺失重试兜底，见 §4）。

## 1. 入口：「+ 新建」弹出菜单分流

首页「+ 新建」按钮不再直接开向导，改为 `.bindMenu` 弹**原生菜单**
（`Menu/MenuItem`——必须用原生组件，自定义拼装的菜单 Button 样式嘈杂，
见 `VmManage.vmOpsMenu` 的既有结论）：

```
        ┌─ + 新建 ─┐
        └────┬─────┘
             ▼
      ┌──────────────┐
      │  模板创建     │  → 打开模板流程（VmTemplate 模态）
      │  自定义创建   │  → 打开手工向导（VmWizard 模态，现状不变）
      └──────────────┘
```

**分流规则**

- **菜单顺序：模板创建在前、自定义创建在后**——模板是普通用户主路径，
  第一眼看到；自定义是进阶入口，沉底。
- 两个流程是**两个独立组件、两个独立模态开关**（`showWizard` /
  新增 `showTemplate`，同在 `Index` `@Provide`），各自挂载、各自关闭，
  不共享状态、无切换关系——用户在菜单里一次选定一条路。
- 「自定义创建」= 今天的 `openWizardNew()`，行为一字不动。

## 2. 模板流程（VmTemplate，单页模态）

复用向导的模态壳（内嵌居中浮层 + 遮罩，样式对齐 `VmWizard`），
内容为**单页表单**，无步骤条：

```
┌─ 模板创建 ────────────────────────────────────────────┐
│  ┌────────────────────────────────────────────────┐   │
│  │ 🐧 Alpine Linux                          内置ISO│   │
│  │ 迷你安全发行版 · 文本模式 · 内置镜像            │   │
│  └────────────────────────────────────────────────┘   │
│  ┌────────────────────────────────────────────────┐   │
│  │ 🪟 Windows XP（选中态）                  自备镜像│  │
│  │ 经典桌面 · 需自备安装镜像 · ide 磁盘            │   │
│  └────────────────────────────────────────────────┘   │
│  ┌────────────────────────────────────────────────┐   │
│  │ 🪟 Windows 7                            自备镜像│   │
│  │ 经典桌面 · 需自备安装镜像 · ide 磁盘            │   │
│  └────────────────────────────────────────────────┘   │
│                                                       │
│  CPU 架构   [x86_64] [i386]          （随模板收窄）    │
│  CPU 核数   ◄───●────────►  1 核（模板默认）           │
│  内存       ◄─────●──────►   512 MB（模板默认）        │
│  系统盘     [4G] [8G] [16G] [32G] [64G]               │
│  安装镜像   [选择 ISO]  未选择                         │
│             Windows 镜像需自备；也可暂不选择，创建后    │
│             到编辑页补挂                               │
│                                                       │
│  其余按推荐默认：ide 磁盘 · rtl8139 网卡 · RTC 本地    │
│                                                       │
│                   [ 取消 ]      [ 创建虚拟机 ]         │
└───────────────────────────────────────────────────────┘
```

**交互规则**

- 模板卡片为**列表单选**（3 张：Alpine 🐧 / Windows XP 🪟 / Windows 7 🪟），
  选中高亮；切模板时表单项重置为该模板默认（arch 回首个可选项、内存/核数/
  盘大小归位），ISO 选择清空。
- **CPU 架构**：6 个内置 ISO 已全覆盖的架构
  （x86_64 / i386 / aarch64 / arm / loongarch64 / riscv64，
  见 `isoDl.specFor`）；切换架构只影响默认值映射与待下载的 ISO，不联动其他可见项。
- **核数 / 内存**：Slider（控件与档位对齐向导步骤③；默认 2 核 / 1024MB）。
- **系统盘大小**：档位列（4/8/16/32/64GB，默认 8GB，动态分配 qcow2）。
- **名称不询问**：自动命名 `Alpine <版本> <架构>`（如 `Alpine 3.21 x86_64`），
  与现有 VM 重名时追加 ` 2`、` 3`… 后缀去重（查 `VmStore.list()` 现有名）。
- 「创建虚拟机」按钮在下载/建盘中禁用并显示进度（见 §4）；「取消」随时可点，
  未落盘前直接关模态不留痕迹。

## 3. 模板固定默认值

模板产物 = 手工向导全默认 + 模板注册表覆盖 + 4 个表单项。三模板对比：

| 项 | Alpine | Windows XP | Windows 7 |
|---|---|---|---|
| 架构 | 6 架构全开 | x86_64 / i386 | x86_64 / i386 |
| 板卡/固件 | 按架构 `fitBoard` | pc / SeaBIOS（**恒 pc**：q35 南桥 ICH9 呈现 AHCI，XP 无 in-box 驱动 → 0x7B 蓝屏） | pc / SeaBIOS |
| 显卡 | std | **cirrus**（驱动 in-box、`vgabios-cirrus.bin` 随包） | std |
| 默认内存/核数/盘 | 1024MB / 2 / 8G | 512MB / 1 / 8G | 2048MB / 2 / 32G（x64 官方要求 20G，qcow2 稀疏） |
| 磁盘接口（v7） | virtio | **ide**（安装程序无 virtio 块驱动） | **ide** |
| 网卡（v7） | virtio | **rtl8139**（XP/Win7 唯一双 in-box；须 `romfile=` 置空——efi-rtl8139.rom 不随包，缺省会拒启） | 同左 |
| RTC | utc | **localtime**（Windows 把 RTC 当本地时间） | 同左 |
| 声卡 | 开 | **关**（AC97 XP in-box 但 Win7 无驱动；XP 用户可在编辑页手动开） | 关 |
| CPU 机型 | 空（qemu 默认） | 空（qemu32/qemu64 是 XP/7 兼容默认，**别改 max**） | 空 |
| ISO | 内置自动下载 | 自备（picker，可跳过） | 自备 |
| 光盘引导 | 是（ISO 必挂） | **选了 ISO 才是**（`-boot d` 无 CD = SeaBIOS No bootable device） | 同左 |
| 表单可调 | 核数/内存/盘 | 核数/内存/盘 | 核数/内存/盘 |

Windows 模板的 IDE 磁盘影响（schema v7）：ide 盘在 `buildArgs` 里显式分配
`-drive index=` 且**跳过 2**（`-cdrom` 固定占 ide index 2，撞上即拒启）；
槽位预算 = 板卡 IDE 槽数（pc 4 / q35 6）− 光盘 1 − 系统盘 1，数据盘上限在
存储弹窗按此收紧，pc 超出槽位的盘会被 qemu **静默丢弃**（guest 看不见且无报错）。
数据盘接口继承系统盘（Windows 下 virtio 数据盘装完系统也看不到）。

## 4. 创建流水线

点「创建」后顺序执行（任一失败即停并 toast 具体原因，按钮恢复）：

1. **落档建盘**：`newProfileId()` → 按 §3 装配 `VmProfile` →
   `createDisk` 建空白 qcow2 → `VmStore.save`。
   （与手工向导 `finish()` 同序：先建盘后落档，取消/失败不留孤儿档。）
2. **获取安装介质**（按模板分流）：
   - Alpine：`ensureBuiltinIso(ctx, vmDataDir, arch, onPct)`，按钮区显示
     `下载中 N%`（已有机制：tuna → ustc 镜像顺序回退）；**ISO 已存在则秒过**
     （多 VM 同架构共享一份，见 `isoDl`）。
   - Windows：**无下载链路**。镜像自备（微软版权），创建时经 picker 选择
     （原地引用，同向导选 ISO 语义）；未选不阻塞创建，toast 提示到编辑页补挂
     （补挂入口自动置 `bootFromCdrom=true`）。
3. **完成**：toast `已创建「<名称>」`，关闭模态，列表刷新（`vmListVersion`）。

**下载失败不毁单**：VM 已落档则保留——`VmConsole.startVm` 本就有
「引导光盘是内置 ISO 且未下载 → 先下载再启动」的首启重试
（`VmConsole.ets startVm`），用户后续启动时自动补下，toast 说明即可。

## 5. 与现有机制的衔接点

| 机制 | 复用方式 |
|---|---|
| 原生菜单 | 「+ 新建」`.bindMenu(Menu{ MenuItem×2 })`，样式对齐 `VmManage.vmOpsMenu` |
| 模态壳 | `VmTemplate` 复用 `VmWizard` 的浮层结构/遮罩/token（独立组件，只借样式不嵌向导） |
| `assemble()` 装配 | 模板流程自己的精简装配函数（默认值常量 + 4 个表单项），产物 schema 相同 |
| `isoDl.ensureBuiltinIso` | 创建时主动调；首启重试兜底已在 `VmConsole` |
| `builtinIsoFor(arch)` | 光盘路径与下载目标的一致性保证 |
| 自动命名去重 | `VmStore(filesDir).list()` 取现有名集合 |
| 校验 | 模板仅 4 项且全是档位/滑块，无非法输入面，无需红字校验链 |

## 6. 扩展位

- ~~模板注册表~~：**已实施（v3）**——注册表内联于 `VmTemplate.ets`
  （`TEMPLATES: TplDef[]`，唯一消费方，不外提 lib）；多模板卡片列表单选。
  新增模板 = 追加一条 `TplDef`（id/图标/描述/架构集/vga/默认资源/diskIface/
  netModel/rtcLocal/audio/iso 策略）。原计划条目「Android-x86 等按卡片样式
  扩充」仍然开放。
- 模板创建后可选「创建并启动」复选（默认关）。

## 7. Windows 模板已知限制

- **网络**：rtl8139（100Mbps 档，XP/Win7 in-box 驱动）。virtio-win 驱动装的
  virtio 网卡更快——编辑页切回 virtio + 自备驱动 ISO 即可。
- **声卡**：默认关。XP 可在编辑页手动开（AC97 in-box）；Win7 开 AC97 无声
  （in-box 的是 Intel HDA，pc 板卡当前固定 AC97，HDA 支持后置）。
- **镜像自备**：Windows ISO 有版权，不随应用分发；XP 已停止支持，
  安装后无安全更新。
- **性能**：TCG 纯软件模拟，XP/Win7 安装与启动均以分钟计，属预期。

## 8. 边界与决策记录

- **无网/下载失败**：见 §4——保档 + 首启重试，不阻塞创建。
- **重复快速点创建**：建盘/下载期间按钮禁用。
- **同架构多台模板机**：ISO 共享不重复下载；系统盘各自独立。
- **为什么不做名称字段**：模板语义是「零决策开箱」，名称自动可后改
  （编辑页已有改名入口）；若评审认为需要，加一行可空文本框（空=自动命名）。
- **为什么是两个独立组件而非向导内分段**（v2 决策）：模板/自定义面向两类
  用户、无中途互换诉求；独立组件让模板流程保持极简单页，也给向导留「我永远
  是 6 步」的干净边界，后续各自演进互不牵扯。
